# Code of Conduct

## Our standards

Eigenflow welcomes technical and scientific collaboration conducted with professional respect.

Expected behavior includes:

- discussing evidence, code, methods, and claims rather than attacking people;
- making disagreements reproducible where possible;
- distinguishing implementation defects from scientific disagreements;
- acknowledging uncertainty and correcting errors;
- respecting privacy and confidential information;
- giving contributors appropriate credit.

## Unacceptable behavior

Unacceptable behavior includes harassment, threats, discriminatory abuse, deliberate exposure of private information, sexualized conduct in project spaces, sustained personal attacks, or knowingly disruptive behavior that prevents technical collaboration.

## Scientific disagreement

Interpretability research often involves contested definitions and incomplete evidence. Disagreement is expected.

When disputing a claim, prefer:

- a counterexample;
- a failing test;
- a reproducible experiment;
- a clearer definition;
- a competing interpretation tied to the same observations;
- evidence that a conclusion depends on an unreported measurement choice.

Do not treat methodological disagreement as evidence of bad faith without independent grounds.

## Scope

This policy applies to repository discussions, issues, pull requests, project communication channels, and other spaces explicitly representing Eigenflow.

## Reporting

Project communication is GitHub-native. Sensitive conduct reports should be directed privately to the repository maintainer, **Andrew Hedman**, through an available private GitHub maintainer channel. Do not place sensitive personal allegations or identifying details in a public issue, pull request, or discussion.

If a matter also involves a security or privacy vulnerability, use the repository's GitHub Private Vulnerability Reporting / Security Advisory channel.

Eigenflow does not publish an email-based conduct-reporting channel and does not use automated conduct-reporting or automated enforcement workflows.

## Enforcement

Andrew Hedman is the project enforcement authority for this release. Reports are reviewed case by case using the available evidence, project scope, severity, and impact on contributors and users.

Possible actions include clarification, content removal, warnings, participation restrictions, temporary or permanent bans from project spaces, and referral to GitHub's platform-level reporting/enforcement mechanisms when appropriate.

Enforcement decisions should minimize unnecessary disclosure of sensitive information and should distinguish good-faith scientific disagreement from harassment or other prohibited conduct.
