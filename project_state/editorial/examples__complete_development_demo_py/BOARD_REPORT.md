# Editorial board report

## Scope adjudicated

## Board synthesis

The software lead requires exact implemented interfaces, explicit portable/runtime persistence boundaries, and runnable examples. The academic review retains the `Q(l,p,t)` formalization but rejects language that equates structural displacement with semantic learning. The methods review requires hypothesis → controlled measurement → compatibility → absolute evidence → displacement → decision ordering. The statistics review makes measurement compatibility, baseline choice, matched probe design, and site-alignment assumptions explicit.

## Conflicts resolved

1. **Observability positioning vs overclaiming:** retain the broader development positioning, but describe diagnostics as evidence for investigation rather than automated architecture/PEFT decisions.
2. **Convenience vs comparability:** convenience helpers may orchestrate checkpoints, but comparison functions must fail rather than silently interpolate incompatible observables.
3. **Summary dashboards vs scalar ranking:** dashboards may colocate behavioral/efficiency/structural evidence; no default universal score is introduced.
4. **Cross-architecture alignment:** exact semantic mappings are preferred; normalized-depth mapping is explicitly approximate.

## Incremental preservation decision

For incremental files, pre-existing adjudicated sections outside the development-instrumentation additions are preserved. Only the new/mutated regions in the scope above are substantively re-adjudicated.
